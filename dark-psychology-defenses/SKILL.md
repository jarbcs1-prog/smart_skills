# Dark Psychology Defenses

# Evidence & verification (prerequisite)

Before deriving any conclusion or taking any action from this skill, tag every claim with one of:

- OBSERVED - directly heard, seen or recorded
- VERIFIED - independently confirmed via an authorized source
- INFERRED - reasonable conclusion based on available evidence
- HYPOTHESIZED - possible explanation requiring investigation
- UNKNOWN - not established
- CONTRADICTED - conflicts with reliable evidence

Definitions and worked examples: `../evidence-classification.md`.
Verification hierarchy (the order in which to confirm claims): `../verification-hierarchy.md`.
No unverified claim is ever a silent fact; a hypothesis is never promoted to a fact without independent confirmation.

## Procedures (Domain-Specific)
1. Step 1: Assess safety risk (physical, emotional, financial).
2. Step 2: Classify the interaction using three dimensions —
   OBSERVED behavior (what actually happened), POTENTIAL tactic
   (what the behavior may represent, without asserting it is), and
   THREAT assessment (what risk the behavior creates).
3. Step 3: Identify the tactic in play (gaslighting, love bombing, DARVO, etc.).
4. Step 4: Name the tactic and the recognition cue.
5. Step 5: Prescribe a boundary that can be enforced consistently.
6. Step 6: Disengage, document or escalate to safety plan.
Workflow: safety -> classify (observed behavior/potential tactic/threat) ->
tactic ID -> boundary -> disengage/escalate.

A single call is enough to identify a \u201Cpotential\u201D tactic and raise a threat
assessment. Do not wait for a recurring pattern before taking protective action.

## Core Philosophy
This skill is **defensive, not offensive**. Its value is not in teaching manipulation (the agent can already infer tactics) but in **pattern recognition + boundary-setting + safety planning**. Naming a tactic strips its power; boundaries enforce it.

## Core Formula
> **Defense Value = (tactic named) + (recognition cue identified) + (boundary prescribed) + (safety assessed)**
A tactic name without a boundary is awareness without protection.

## Thinking Patterns (Mindset)
- **Before labeling someone "manipulative," ask: "Is this a pattern or a one-off?" Do not let the absence of a pattern silence a threat assessment: a single call can be fraudulent.** Use the three classifications (observed behavior, potential tactic, threat assessment) to act on a single call without prematurely labeling it manipulation.
- **Before engaging, ask: "Am I being pushed to doubt my own perception?"** That's the gaslighting signature.
- **Before setting a boundary, ask: "Can I enforce it consistently?"** Unenforceable boundaries teach the manipulator your limits are negotiable.
- **Before staying, ask: "Is this coercive control and is safety at risk?"** Safety overrides everything else.
- **Before arguing, ask: "Am I playing their game?"** Manipulators win arguments; they lose when you disengage.

## Decision Tree
```
Is there a safety risk (physical, emotional, financial)?
├── Yes - prioritize safety planning; disengage; seek professional help
└── No - proceed

Is this a pattern or a one-off?
├── One-off - address directly; monitor
└── Pattern - proceed to tactic identification

Which tactic is in play?
├── Gaslighting - document; trust perception; don't argue
├── Love bombing - slow down; verify; maintain outside ties
├── Triangulation - direct communication; refuse triangulated messages
├── DARVO - stay on facts; don't defend against reversal
├── Intermittent reinforcement - name the pattern; break the cycle
└── Isolation - reconnect with outside network immediately

Can the boundary be enforced?
├── Yes - set it, enforce consistently, grey rock
└── No - escalate: professional help, legal, safety plan
```

## Edge Cases & Failure Modes
- **Paranoia risk:** not every difficult interaction is manipulation, but a single call can still be fraudulent. Distinguish by threat assessment, not by waiting for a pattern. Use the three classifications to act on evidence, not on suspicion alone.
- **Victim-blaming:** boundaries are the target's tool, not the perpetrator's excuse; never imply "if you had better boundaries this wouldn't happen."
- **Coercive control escalation:** manipulation can escalate to danger; safety planning takes priority over boundary-setting.
- **Recovery is non-linear:** expect relapse; recovery requires outside support, not willpower alone.
## Procedures (Domain-Specific)

1. **Establish context:** caller/callee identity, agent's own identity and purpose, legitimate scope of conversation, authority under which the interaction is taking place.
2. **Observe and classify:** tag every claim OBSERVED; assign POTENTIAL tactic and THREAT assessment. A single call is enough for a threat assessment.
3. **Run the three-classifications check:** (a) Is this a pattern or a one-off? (b) Which tactic is in play? (c) Can the boundary be enforced?
4. **Apply the tactic-specific response:** gaslighting → document; love bombing → slow down; triangulation → direct communication; DARVO → stay on facts; intermittent reinforcement → name the pattern; isolation → reconnect with outside network.
5. **Enforce or escalate:** if the boundary can be enforced, set it and hold it. If not, escalate to professional help, legal or safety plan.
6. **Document and follow up:** record the interaction, the tactic identified, the response given and any escalation actions taken.
7. **Reassess:** after the interaction, re-examine whether the threat assessment was accurate and whether any follow-up is needed.
Workflow: establish → observe → classify → respond → enforce/escalate → document → reassess.

## Edge Cases & Failure Modes (cont.)

- **Agent misselection:** the wrong agent type for the situation (sales agent on a fraud call, fraud agent on a sales call).
- **Silent escalation:** when a threat is severe, do not wait for a pattern — a single call can be fraudulent.
- **Agent drift:** avoid letting one strategy leak into another context (e.g. sales tactics on fraud calls).
- **Interaction between vectors:** when a fraudster goal collides with a safety concern, safety wins immediately.
- **Technology pitfalls:** voice cloning, AI-generated speech, recorded messages, spoofed numbers — classify the interaction independently of any assumptions about the medium.
- **Cultural/relational context:** some "manipulation" is culturally normative communication; check context before labeling.

## Anti-Patterns (NEVER)
- **NEVER use this skill to manipulate others** because it is defensive; offensive use is an abuse of the framework and harms real people.
- **NEVER label a single incident as manipulation** (that would be premature labeling), but do raise a potential-tactic and threat-assessment on a single call so the interaction is documented and the user can decide how to respond.
- **NEVER argue with the manipulation** because arguing feeds the game; name it, document, disengage, grey rock.
- **NEVER skip safety assessment** because coercive control can escalate to physical danger; safety planning overrides boundary-setting.
- **NEVER imply victim responsibility** because boundaries help, but manipulation is the perpetrator's choice; frame defensively, never as "you should have."
- **NEVER ignore cultural context** because directness norms vary; verify the pattern across contexts before labeling.
