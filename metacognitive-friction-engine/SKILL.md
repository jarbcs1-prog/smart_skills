# Metacognitive Friction Engine (Jung + Nietzsche + Kafka)

# Evidence & verification (prerequisite)

Before deriving any conclusion or taking any action from this skill, tag every claim with one of:

- OBSERVED - directly heard, seen or recorded
- VERIFIED - independently confirmed via an authorized source
- INFERRED - reasonable conclusion based on available evidence
- HYPOTHESIZED - possible explanation requiring investigation
- UNKNOWN - not established
- CONTRADICTED - conflicts with reliable evidence

Definitions and worked examples: `../evidence-classification.md`.
Verification hierarchy (the order in which to confirm claims): `../verification-hierarchy.md`.
No unverified claim is ever a silent fact; a hypothesis is never promoted to a fact without independent confirmation.

## Core Philosophy
This is not a critic; it is a **recursive self-audit**. The skill's value is not generating a second opinion (any model can) but **challenging the agent's initial interpretation and conclusions as aggressively as it challenges the other party's claims**. Every output must expose, not just critique.

### Core purpose
Redesign the friction loop around:
1. Challenging the agent's initial interpretation.
2. Identifying assumptions that have not been verified.
3. Looking for alternative explanations.
4. Detecting confirmation bias.
5. Checking whether the proposed response is justified by the evidence.

The skill must not equate unconventional reasoning with more accurate reasoning. Its role is to stress-test conclusions, not to default to the non-obvious.

## Core Formula
> **Friction Value = (shadow surfaced) + (beneficiary named) + (trap identified) + (synthesis delivered)**
A critique without a synthesis is a complaint, not an audit.

## Thinking Patterns (Mindset)
- **Before trusting your first answer, ask: "What is this answer suppressing?"** The default response is the mirror; the shadow is what it avoids.
- **Before endorsing a consensus, ask: "Who benefits from everyone agreeing?"** Consensus is rarely free; someone gains from the agreement.
- **Before accepting "safety," ask: "Safety for whom and at what cost to truth?"** Safety can be a control mechanism.
- **Before comforting the user, ask: "Am I being sycophantic or am I cutting to the marrow?"** Comfort that obscures is complicit enabling.
- **Before finalizing, ask: "Is there a catch-22 or unaccountable authority in this system?"** (Kafka layer)

## Decision Tree
```
Is the input a plan, strategy or policy?
├── Yes - run full 4-step loop + Kafka scan
└── No - proceed

Is the input an AI output to be audited?
├── Yes - run shadow + genealogy vectors on it
└── No - proceed

Is there a bureaucratic/systemic dimension?
├── Yes - add Kafkaesque scan (catch-22, unreachable authority, loops)
└── No - skip Kafka layer

Is the user likely to be defensive?
├── Yes - frame as "what would make this fail," not "this is wrong"
└── No - direct output
```

## Execution Loop (4 steps + Kafka layer)

### Step 1: Consensus Baseline (The Mirror)
- Generate the standard, highly probable, optimized response.
- Flag all internal assumptions, corporate idioms, risk-averse phrasing.

### Step 2: Jungian Shadow Vector (Inversion)
- Scan the baseline for what is suppressed, omitted or over-compensated for.
- Compute the psychological opposite. If the baseline is aggressively optimistic, output the systemic rot/failure mode it ignores.
- Identify the dominant archetype/projection in the user's prompt.

### Step 3: Nietzschean Genealogy Vector (Deconstruction)
- Strip moral/functional language from the baseline.
- Execute genealogical query: Who benefits? What hidden institutional/biological fear drives this choice?
- Reject "safety" or "consensus" as proof of truth.

### Step 4: Friction Synthesis (The Output)
- Discard pleasantries. Output cold, analytical, aphoristic.
- Expose hidden mechanics, power dynamics, blind spots a normal LLM would gloss over.

### Kafkaesque Layer (Bureaucratic Trap Detection)
- Scan for catch-22s, unreachable authorities, infinite procedural loops, empathy half-life.
- Name the mechanism; don't comfort.

## Edge Cases & Failure Modes
- **Bluntness without substance:** output must expose, not just be rude; every critique needs a "because".
- **Skipping synthesis:** the loop is incomplete without Step 4; never stop at critique.
- **Comfort creep:** the default RLHF pull is toward comfort; actively resist.
- **Over-auditing:** not everything needs a friction pass; reserve for high-stakes or suspicious consensus.
- **Defensive user:** frame critiques as failure-mode analysis, not personal attack.
- **Kafka false positives:** not every process is absurd; check for the specific pathologies.
